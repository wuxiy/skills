# Creating New Skills

How to add a skill to `cywu-skills`. Adapted from the conventions used by [JimLiu/baoyu-skills](https://github.com/JimLiu/baoyu-skills), right-sized for this library.

## Key Requirements

| Requirement | Details |
|-------------|---------|
| **Location** | `skills/<name>/` at the repo root (NOT `.claude/skills/` — that's a project-local install path, not the library layout) |
| **Prefix** | All skills MUST use the `cywu-` prefix (e.g. `cywu-code-refactor`) |
| **`name` field** | Max 64 chars, lowercase letters/numbers/hyphens only; no `anthropic`/`claude` |
| **`description`** | Max 1024 chars, third person, include **what** it does **and when** to use it. List concrete trigger phrases (both Chinese and English where relevant). Slightly "pushy" to counter Claude's tendency to under-trigger |
| **SKILL.md body** | Keep under ~500 lines; push detail into `references/` (one level deep) |
| **Self-containment** | A skill folder is consumed independently. Never link from `SKILL.md` or its `references/` to files outside the skill's own directory (no `../../docs/…`, no sibling skills). Inline any shared convention directly in the skill |

## SKILL.md Frontmatter Template

```yaml
---
name: cywu-<name>
description: >-
  <Third-person description. What it does + when to use it, including trigger phrases.>
version: <semver>
---
```

## Directory Layout

```
skills/cywu-<name>/
├── SKILL.md              # Main instructions (<500 lines)
├── references/           # Optional: detail loaded as needed (one level deep)
├── scripts/              # Optional: executable code for deterministic tasks
└── evals/                # Optional: test cases + fixtures + eval evidence
    ├── evals.json
    ├── setup-fixtures.sh # regenerate fixture projects (gitignored, often contain nested .git)
    ├── grade_runs.py     # programmatic assertion grader
    ├── fixtures/         # gitignored — rebuilt by setup-fixtures.sh
    └── iteration-N/      # eval evidence (benchmark, reports, grading, timing)
```

## Steps

1. `mkdir skills/cywu-<name>` and write `SKILL.md` with frontmatter
2. Add `references/` for any section that would push SKILL.md past ~500 lines
3. Add `scripts/` if the skill needs deterministic code (note runtime in SKILL.md)
4. (Optional) Author evals with the `skill-creator` skill: `evals/evals.json` + fixtures; commit `setup-fixtures.sh`, the grader, and iteration evidence; gitignore regenerated fixtures and bulky `outputs/work/` copies
5. Register the skill in [`.claude-plugin/marketplace.json`](../.claude-plugin/marketplace.json) under `plugins[0].skills`
6. Add a one-line entry to [README.md](../README.md) and [CLAUDE.md](../CLAUDE.md)

## Writing Descriptions

Third person, include triggers. Example:

```yaml
# Good
description: >-
  This skill should be used when the user asks to "重构", "优化代码", "refactor", or
  when the user has just finished a feature and wants it re-reviewed for duplicated
  logic, design, UI consistency, and performance. Use it whenever the user asks to
  optimize already-written code, even if they don't say "refactor".

# Bad
description: I can help you refactor code
```

## Tooling Notes

- The `skill-creator` skill (in `skills/skill-creator/`) is the authoring/evaluation tool. Its Python scripts require **Python 3.10+** (Homebrew `python3.14`; the system `python3` is 3.9 and fails on `dict | None` annotations).
- Eval fixtures that need git history are regenerated by a `setup-fixtures.sh` (gitignored, since they contain nested `.git`). Document the regen command in the skill's `evals/`.
