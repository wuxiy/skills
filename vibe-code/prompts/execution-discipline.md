# 执行纪律：拆单落盘 + 主 Agent 串行 + Codex Review 门禁

> 一套约束 AI 全栈交付过程的硬规则：工作按 PRD 顺序拆成清单落盘、主 Agent 从上到下串行完成、每完成一条立即 Codex Review 门禁、全程禁止过度设计。保证进度可视、续跑有真相、产出不失控。

## 规则原文（复制即用，写入 AGENTS.md / 项目规则）

### 开工
- 先按 **PRD 章节顺序**把全部工作拆成**有序任务清单**，落盘为**可勾选文件**（如 `TASKS.md`）。
- **续跑以它为进度真相**，禁止跳项。

### 执行
- 必须由**主 Agent 从上到下一条一条完成**。
- **禁止** worktree、**禁止**新建分支、**禁止** subagent 或并行。

### Review 门禁
- 每完成一条，**立即**跑 `/herdr`（`codex --yolo`）进行 review，必须使用 **GPT 5.6 sol max** 模式。
- 有问题**先修复并复审通过**，才能进下一条。
- 同一条目**最多 review 3 遍**——所以实现必须一次做仔细，争取首轮过审。

### 禁止过度设计
- 无论**主 Agent（Fable 5.1）的实现**还是 **Codex review 的意见**，都禁止过度设计：只做要求的，**不加抽象层、不做预留扩展**；review 不得以"建议增强"为由打回。

## 为什么有效

- **拆单落盘**：AI 长任务最容易"跑着跑着忘进度"，清单是唯一进度真相，续跑/换人/隔天都能精确续上。
- **禁止并行与分支**：worktree/分支/subagent 会制造多份上下文碎片，验收和合并成本远超并行收益；串行一条条过，每一条都是被验证过的稳定增量。
- **Review 门禁**：完成 ≠ 正确，每次变更立即过一遍独立 review，错误在产生时就被掐死，而不是堆到最后一起爆。
- **3 遍上限**：倒逼"一次做对"，避免 AI 用"慢慢试"掩盖实现质量。
- **禁止过度设计**：AI 的默认倾向是加抽象、留扩展、讨好式增强——这些全是隐藏维护成本。规则明确"只做要求的"，review 也不得以"建议增强"打回，杜绝无限扩展。

## 注意点

- 这里的模型/工具名（Fable 5.1、GPT 5.6 sol max、/herdr + codex --yolo）是具体团队配置，换成你自己的 harness 即可，规则骨架不变。
- 清单文件本身也是工作产物：每条完成后顺手勾选/标注，保持"进度真相"永远新鲜。
