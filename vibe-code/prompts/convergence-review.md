# 多轮修改后的收敛复核（强制）

> 一条 Coding Agent 规则，专治"改了多轮定位到根因，却把探索过程的临时分支/兜底/重复逻辑全留在代码里"导致的屎山。适用 **Codex、ClaudeCode 等 Coding Agent**，可直接写入 `AGENTS.md` 或 `CLAUDE.md`。

---

## 规则原文（复制即用）

**多轮修改后的收敛复核（强制）**：同一问题经过多次代码调整后才定位根因时，完成实现后 Agent 必须**自主发起一次"最终行为最小改动" review，不得等待用户提醒**。

复核应确认：
1. **根因修复是否已覆盖目标行为**
2. **是否与同类相似功能的既有模式一致**

并执行清理：
- **删除或回退**探索过程中加入但最终不再需要的临时分支、兜底、重复逻辑和额外刷新/重载
- 对**保留的非显而易见约束补充中文 WHY 注释**，说明字段语义、状态生命周期或时序边界

**目的**：避免后续排查再次沿错误假设扩散。

---

## 为什么有效

AI 修复一个反复出现的问题时，往往经历"试 A → 试 B → 终于定位根因"的探索过程，期间会塞进各种临时的 `if` 兜底、额外 `refresh()`、重复的错误分支。根因找到后，这些探索痕迹如果不清，就成了最隐蔽的屎山来源——**看着能用，实则藏着死代码和错误假设**。

这条规则强制 AI 收敛到**最终行为的最小改动**，而不是把打过补丁的探索路径原样上交。
