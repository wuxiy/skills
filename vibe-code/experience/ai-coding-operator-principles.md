# AI Coding 操控者原则：质量跟人走，不跟工具走

> 来源：Joway《关于 AI Coding 的一些个人技巧》https://blog.joway.io/posts/ai-coding-principle/（2026-09-19）
>
> **核心论断**：在合理的使用方式下，用不同工具和各家最新一代模型，产出不会有太大质量差异——如果有，说明你没驾驭住它们的特点，全在任凭模型自我发挥。"模型是模型，人是人，正确的 AI Coding 应该是**产出质量跟操控者走，而不是跟着工具和模型走**。"（就像驾驶员该掌握开不同车用不同开法，而不是非法拉利不开。）

---

## 1. 质量远高于速度

- 犯大错的机会是有限的：中国大公司约 **1 次**、外企约 **3 次**、创业公司 **4-6 次**。正经工作对错误的容忍度不高
- 作者日常**并行最多 3 个窗口**——再多，脑子已经忙不过来去检查每个 Agent 的成果了
- 很少有公司因为你慢一点开除你，但经常因为大事故开除人。**编程速度的问题早已解决，现在的问题是质量**

## 2. 不要过度使用 Skill —— "只有模型和巴菲特都不知道的知识，才用 Skill"

判断标准一句话：**模型不知道、巴菲特也不知道的知识，才值得装 Skill**。

- ✅ 该装：x.com 的 API 怎么调、浏览器怎么自动化（模型训练数据里没有的**事实性/工具性知识**）
- ❌ 不该装：批判性思维、实现前多问几遍、正确提问（**通用思维方法论**模型本来就会）

装"思维方式类 Skill"的三个坏处：
1. Overthinking 本来就是模型天生缺点，这类 Skill 会放大它
2. Skill 装多了，你分不清哪些是模型内置思考、哪些是 Skill 引导、哪些是你自己的引导
3. 大多数人装前不会读完 Skill——不知道 Skill 会干嘛，就无法预期会话产出，等于**黑盒编程**

作者自己只留 2 个 Skill（Lark 协同、浏览器自动化），所以能清楚预期模型反应：想要批判性思考时它就批判，想让它别多想使劲干它就使劲干。

> 如果你觉得某人的思维方式很好，**你应该学习这个人的思想，然后去操控模型**——而不是去 GitHub 找一个"某某 Skill"装上。

## 3. 少命令，多提问

同一个需求（注册后发邮件）的三种提示词：

| 提示词 | 类型 | 结果 |
|--------|------|------|
| A：`/register 接口下调用 resend 接口发一封注册邮件` | 精确命令 | 模型照做、不深度思考，你也没思考需求的复杂性，隐患落进代码 |
| B：`注册后发一封邮件` | 模糊命令 | 模型闷头实现，对错难说，实现方式纯黑盒 |
| C：`我想要实现发注册邮件的功能，**有哪些**实现方法？` | 提问 | 模型深度思考多方案（简单实现 vs 发注册事件+consumer 幂等消费直到成功），**最后拍板的人是你** |

魔法词是"**哪些**"——逼模型给出方案空间而不是单点答案。**这才叫驾驭模型**。而且这个需求看似简单，其实藏着真问题：resend 挂了注册接口返回成功还是失败？失败重试怎么做？总不能同步等重试吧？

## 4. 控制设计而不是代码

- 几百行以上的改动，**先让 AI 生成设计文档**（富文本，带架构图/流程图——Lark 文档或 HTML 都行，别用纯文本糟蹋了图的表达力）
- 你理解了设计，才能提出比 AI 更有价值的见解，去优化或简化设计
- 设计文档也能帮 review 你代码的人快速理解实现。**现在的模型很难出现"设计对、代码错"的情况**——所以按 PR 重要性决定是否 review 代码，重点放在控制设计

## 5. 选择性向后兼容

- 模型有个习惯：爱写向后兼容的代码，代价是代码越写越脏越复杂
- 模型不知道你们的部署顺序、不知道产品是否已上线有真实用户、不知道是否允许停机维护——**但你知道**
- 如果允许破坏兼容性，就明确让模型写**最优解**，不管兼容——这对项目长期维护价值巨大

## 6. 善用 AI Review，但反对纯 AI Loop

- 代码生产速度下，人力 Review 已不现实，AI Review 是对的
- 但 **100% 反对**"Agent 写码 → Agent Review → Agent 按 Review 意见改"的自动循环：
  - Review Agent **共享**上下文 → 意见不客观；**不共享** → 上下文不充分
  - 还有一部分上下文只在使用者脑子里
  - AI 自循环的结果不确定，甚至可能偏离最初意图
- 正确姿势：**AI Review → 人工检查并筛选意见 → 摘取部分交给 Coding Agent 修改 → 反复**。慢，但质量提升必须由人类明确知道是哪些

## 7. 保持勤奋

- 上面每条每次对话都能做到吗？完全不能——**比模型更喜欢偷懒的是人**
- AI 可以 10 分钟干完，也可以对话十几轮花几小时；没人审核你的勤奋度，全靠自觉
- 加班到很晚，产出质量可能只从 80 → 90 分，值得吗？——至少**在重要的事情上保持勤奋**，这比所有奇技淫巧都重要
