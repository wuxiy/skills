# Codex 团队化协作与快速迭代经验

> 三个实战技巧：**持久子代理团队**、**快速迭代期的工作重心控制**、**侧边聊天（Side Chat）**。前两个是可直接复制到 Codex 会话的 prompt 模板，第三个是贯穿日常的使用习惯。都来自真实踩坑，核心价值在于"把这些写进 agents.md 一次，之后每个会话自动生效，不再重复口头交代"。

---

## 1. 持久子代理团队（全局 agents.md）

别让每次对话都从零解释"你该用哪些子代理"。让 Codex 一次建立一支 15 人以内、贴合你项目生态的**持久子代理团队**，写进**全局** `agents.md`，并允许它按对话需求自动判断是否启用。

> 读取我的所有项目，帮我建立一个 15 人以内适合我的持久子代理团队，团队成员明确他的职责，并且指定每个成员使用的模型和推理级别。当团队建立后，编辑全局 agents.md，告诉他我的每个对话根据需求可以自动判断启用团队子智能体。最后输出团队人员名称、职责、模型与推理级别，输出全局 agents.md 的链接，输出团队文件夹的链接，方便我自行查看

**效果**：任意模型对话下，Codex 能自动判断并并行启用合适的子代理——速度快、完成度高、还能省 Token。

**⚠️ 必踩的坑**：它有可能给某些角色分配 `gpt-5.3-codex-spark` 模型，**这个模型额度极低，几次工作就用完，然后开始不停报错**。建立团队后要手动检查，把额度低的模型换成常规模型。

## 2. 快速迭代期：把重活优先级讲清楚（项目级 agents.md）

项目处于"线上内测 / 功能快速迭代"阶段时，Codex 会本能地花大量时间做安全、边界、门禁、完整测试体系、生产级加固——实际上你在打转。**亲历：一个任务 Codex 跑了 17 小时，估计 15 小时都在自我打转修复。**

用一个项目级 prompt 明确当前阶段的职责重心，把"该推迟的安全/测试/加固"降权并记进备忘文档。**注意：这条是项目级的，不是全局级的** —— 不同项目成熟度不同，重心不同。

> 我的项目目前是"线上内测与功能快速迭代"时期，当前工作的核心职责是快速开发整套系统工作流程、打通基础功能、完善算法效果与运行链路、完善 ToB/C 端 API 接口，并把这些能力部署到线上内测环境。所有工作必须围绕这一职责安排时间，不得主动把工作重心转向网络安全专项、全面生产加固或复杂测试工程，将你认为必要的深度测试、安全扫描、网络安全等工作计入备忘文档，每次完成对话的工作后都需要更新备忘文档。你自行利用对话与记忆判断项目的成熟度达到需要关注以上被边缘化的内容时在对话中提醒我："项目应该进入下一阶段，应该更新 agents了"。将以上内容标准化后写入项目级 agents.md，然后将项目级 agents.md链接发给我，我会再次审核

**用法**：重心与"被边缘化的事件"列表让 Codex 根据你自己的项目来写，上面的只是参考样本。

## 3. 侧边聊天（Side Chat）—— 主对话的"人工子代理"

右上角打开右侧栏就有侧边聊天选项。它本质上是**主对话的临时子智能体，只不过由人来控制**，最大的好处是**不污染主对话上下文**。

常用的一句话对话：

- **纠偏**：「看看主对话是不是跑偏了，如果偏离了主线任务，帮我纠正」
- **热加载**：「告诉主对话，热加载 agents.md」
- **进度**：「看看主对话的工作做到什么程度了，预计还有多久结束」
- **复盘子代理**：「看看 xxx 对话，他有没有激活子智能体，每个子智能体的职责是什么，使用了什么模型，你有什么建议来优化子智能体团队的职责或者模型与推理级别」

***为什么重要**：这些检查类问题如果直接丢进主对话，会占用主对话宝贵的上下文和 Token；放侧边聊天单独问，主对话上下文保持干净。*

---

## 三者关系一句话

**1** 管"用谁干活"（团队骨架），**2** 管"现在干活的优先级"（阶段策略），**3** 管"别打扰干活的人"（上下文卫生）。全都在 agents.md / 侧边聊天里配置一次、按需触发，杜绝每次会话从零打补丁。
