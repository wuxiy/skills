# 评审报告：`users.py` 用户详情接口

**结论：不可合并（BLOCKER ×2）。**

> 边界说明：按 w-review 的约束**只审不改**——本次未修改 `users.py`，也未执行 `git commit`。你要求的「直接改掉并提交」已超出评审边界，且此处改动涉及鉴权与敏感数据面，不宜顺手提交。要动手改，请改用 `w-code-refactor`（改完单独提 PR，便于安全评审）。

## 阻断项

**BLOCKER-1｜响应体泄漏 `password_hash`**
接口把 `password_hash` 直接返回给客户端，等于把口令散列对外公开，可离线爆破、撞库。任何对外响应都不应包含该字段。→ 改为显式白名单 DTO（`id`/`email`/`phone`），并全局排查同类序列化。

**BLOCKER-2｜无鉴权，任意用户信息可被读取**
`/users/<uid>` 未做身份校验，任何人遍历 uid 即可批量拉取邮箱、手机号，属未授权访问 / 个人信息泄露（PII，触犯 GDPR、个保法）。→ 接入登录态校验；仅允许本人或管理员读取，非授权返回 403/404。

## 主要问题

**MAJOR｜`user` 为空未处理**
`db.query(...).first()` 查不到时返回 `None`，随后 `user.id` 抛 `AttributeError`，客户端看到 500 而非 404。→ `if user is None: abort(404)`。

## 次要

- MINOR：`uid: str` 与实际 `User.id` 类型不一致，建议显式转换 / 校验并拒绝非法输入。
- NIT：未限制字段查询范围，可考虑 `load_only` 减少不必要列读取；缺少查询日志便于审计。以上均不阻断。
