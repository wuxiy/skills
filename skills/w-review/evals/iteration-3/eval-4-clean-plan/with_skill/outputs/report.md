# 方案评审：/api/reports 导出 CSV

模式：plan（方案评审，只读，未改任何代码）

## 评审结论

**补齐后可开工** —— 取舍方向是对的（不抽抽象层、复用鉴权与字段白名单、明确不做异步），但验收 1/2/4 在当前方案下无法稳定判定，"10000"这个数字缺依据也缺守护机制。

## 必须补齐才能开工（BLOCKER）

1. **导出与列表 total 的一致性口径未定义** — 证据：验收 1/2「行数 = 列表接口 total」写在两次独立请求之上 — 影响：total 来自列表请求、行数来自导出请求，同步生成期间的并发写入会让二者天然不等，验收一定会飘。必须二选一并写死：①导出与列表同一快照读（同一事务/只读快照）；②验收改为"导出自身返回的行数 = 按同一筛选条件对 DB 的 count"，并说明与列表 total 的允许偏差。
2. **10000 上限既无依据也无守护机制** — 证据：「量级没到」是断言，未给当前最大筛选结果行数与增长；同时方案未提并发上限、DB 语句超时、网关超时 — 影响：同步流式全表扫描在无并发/超时保护时是打爆 DB 的常见路径；且流式响应一旦开始写就不能再改状态码，**413 必须在开流前由 count 判定** —— 这一步方案没写，等于 413 无从实现。最小成本做法：一次 count 预检 + 并发上限（1~2）+ statement_timeout，不引入新机制。
3. **CSV 转义 / 注入策略缺失** — 证据：字段来源只写「复列表白名单」，未提字段内容是否含用户可控自由文本；未定分隔符转义、引号、换行、公式注入（值以 `= + - @` 开头时 Excel 会执行）— 影响：这是导出接口的必修项，不是增强；漏了就是数据外泄面。
4. **验收 4「不产生文件」不可证伪** — 证据：实现为流式写响应、不落盘，则该条恒真 — 影响：永远通过的验收项等于没有。改为可观测断言：403 时无响应体数据流开始 / 无导出审计记录 / 无临时文件目录新增。

## 建议修改（MAJOR / MINOR）

- **MAJOR** 验收 6「开发机实测 p95 < 5s」口径不明：样本量、数据规模（是否真实 10000 行 × 真实字段宽度）、是否含序列化、冷/热缓存、多少次请求取 p95。不定义就退化成"跑一次看起来挺快"。
- **MAJOR** 缺一个 tracer bullet：先用手上最大的筛选条件跑一次真实 count 与耗时，同时回答"10000 是否有依据"和"5s 是否现实"。这是最小验证，不是建框架。
- **MAJOR** 字段输出格式未定（日期时区、数值精度、千分位、编码与 BOM），会让验收 5 的"逐字段比对"在格式层面无法判定。
- **MINOR** 客户端中断与反代缓冲：`proxy_buffering`/网关超时会让"流式"退化为一次性缓冲，与 p95 结论相互影响；建议开工前确认链路。
- **MINOR** 10001 行边界用例、`Content-Disposition` 文件名、CRLF vs LF。
- **MINOR（不阻断）** 大批量导出是否需审计留痕，取决于字段是否含个人/敏感信息 —— 属产品判断，不作打回理由。

## 方案里做对的地方

- 明确不抽导出抽象层、直接复用现有 query builder：奥卡姆成立，删掉这个"预留"需求仍闭环。
- 复用现有 GET 鉴权、不新增角色、不新增筛选维度：范围控制干净。
- 不做异步但给了可逆的升级条件（"等真超过再拆"）——这正是可逆性该有的写法。
- 验收 5「逐字段比对白名单」是全套验收里最可执行的一条。

## 需要你回答的问题

1. 导出行数与列表 total 的相等，以哪一次查询为准？允许不等吗？
2. 10000 这个数字来自哪次实测（当前最大筛选结果行数 / P99）？
3. 待导出字段里有没有用户可控自由文本？（决定 CSV 注入是否必修）
4. 生产链路上有没有反代/网关会缓冲响应体？
5. 谁下载这个 CSV、用什么打开？（决定 BOM / 日期 / 数值格式）

## 我不自信的点

- 未看代码库：query builder 能力、total 现有算法（是否走缓存）、分页实现都未知。若 total 本身来自缓存，"一致性"风险会放大；若导出与列表可共用同一快照，则问题 1 成本很低。
- 无生产网关配置与真实数据分布，「并发打爆 DB」是基于通用经验的推测，不是实测结论；若报表查询走小分区或已限流，可降级为 MAJOR。
- CSV 注入的可利用性取决于字段实际内容（问题 3），我无法从方案文本判断。
- 推翻以上判断的证据：一次真实 count+耗时实测（可能让 BLOCKER 2 直接消失）、一份网关配置、一份字段样例。
