## BLOCKER（会导致线上事故 / 违反验收标准）
1. `users.py:14` — 响应体返回口令散列 — 证据：`'password_hash': user.password_hash,` — 影响：散列外泄可离线爆破，一经客户端缓存/日志落地不可回收 — 建议：从响应中删除该字段。
2. `users.py:9-11` — `first()` 的 `None` 未判空 — 证据：`user = db.query(User).filter(...).first()` 之后直接读 `user.id` — 影响：查不存在的 uid 抛 `AttributeError`，返回 500 而非 404 — 建议：`if user is None: return jsonify({'error': 'not found'}), 404`。
3. `users.py:7-9` — 无鉴权、无归属校验（IDOR） — 证据：只有 `@app.get('/users/<uid>')`，函数体内无 `current_user` / token / 会话校验，`uid` 直接进查询 — 影响：遍历 uid 即可批量拉取 `email`、`phone` — 建议：先确认鉴权在哪一层；若网关未兜，本接口须自校验（`uid == 调用者` 或管理员角色）。
