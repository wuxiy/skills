## 最终重构方案

**思路**：不整理补丁，而是带着对完整需求的理解重新推导。收敛后的完整需求 = 首版规则 + 三个补丁确立的行为：

1. 折扣码按比例减价；**未知/空的码按无折扣**（原 `31a1dfa`）
2. VIP 会员额外 9 折
3. 可叠加码先折扣码后会员折扣；**不可叠加的活动码与会员折扣互斥，取更优惠者**（原 `4e35f0a`）
4. **负价格按 0**（原 `f5e0d83`）
5. 结果四舍五入到分

**核心设计变化**：

```js
// 折扣码表：rate = 减价比例；stackWithVip = 是否与会员折扣叠加
const COUPONS = {
  SAVE10: { rate: 0.1, stackWithVip: true },
  SAVE20: { rate: 0.2, stackWithVip: true },
  VIP50:  { rate: 0.5, stackWithVip: false },
};

function calcFinalPrice(price, coupon, isVip) {
  const base = Math.max(0, price);                  // 1. 边界校验收敛到入口
  const def = COUPONS[coupon];                      // 2. 查表未命中 -> 无折扣
  const couponPrice = def ? base * (1 - def.rate) : base;
  if (!isVip) return roundToCent(couponPrice);
  const vipPrice = base * VIP_RATE;
  const finalPrice = def && !def.stackWithVip
    ? Math.min(couponPrice, vipPrice)               // 3. 互斥取更优惠（数据驱动）
    : couponPrice * VIP_RATE;
  return roundToCent(finalPrice);                   // 4. 单一取整点
}
```

- **控制流问题还原为数据问题**：`coupon === 'VIP50'` 特判消失，`stackWithVip` 成为码表属性；新增任何活动码只需加一行数据
- **校验集中到边界**：负价格在入口钳制，未知码在查表时消解；计算主体不再有任何防御分支
- **`roundToCent` 提取**：取整逻辑单点
- **兼容保持**：`COUPON_RATES` 导出按原形状 `{ SAVE10: 0.1, ... }` 从码表派生保留；纯函数、无副作用、无对象 mutate

**覆盖核对**（原补丁链每个症状 → 新实现中的保证）：

| 原补丁解决的问题 | 新实现中由哪里保证 |
|------------------|--------------------|
| 未知折扣码不得 NaN（31a1dfa） | `COUPONS[coupon]` 查表，未命中 → `couponPrice = base` |
| VIP50 不与会员折扣叠加、取更优惠（4e35f0a） | `stackWithVip: false` → `Math.min(couponPrice, vipPrice)` |
| 负价格输入兜底 0（f5e0d83） | 入口 `Math.max(0, price)` |
| 首版全部规则（4d35f40） | `(1 - rate)` 减价、`* VIP_RATE` 叠加顺序、`roundToCent` |
